# Frictions — DSS concepts Alteryx users push back on

Open this when the complaint is about *how DSS works*, not a specific tool. These are onboarding reframes — treating them as gaps is the #1 reason migrations stall. Each row: user says → reframe / point at.

| Friction (user says) | Reframe / point at |
|---|---|
| "40 datasets in the Flow, I only want the final one — storage wasted, Flow cluttered" | Flow Zones (chunk Flow); SQL pipelines (collapse all-SQL chain to one compiled query, no intermediates materialized); **Clear intermediate datasets** plugin (dataiku-contrib) in a scenario post-build step. Alteryx materializes nothing between tools (desktop, single-process); DSS materializes every intermediate → inspect, resume from checkpoint, rebuild only changed, run recipes on different engines. Server-paradigm feature, not an artifact. Prod refactor: don't chain Prepares (collapse to one), use recipe pre-/post-filters + computed cols, SQL pipelines for all-SQL segments. |
| "I see data change with every tool in Alteryx; here I run, wait, open output — too slow" | Recipe dataset previews (recent DSS) show output sample in the edit page; Prepare's script view is already live on a sample; **Run on sample** (recipe sample-size setting) for heavy inputs; open input + output in two browser tabs — DSS is web-native, not one-window desktop. |
| "Alteryx shows row counts next to every tool — how do I spot a recipe that blew up the count?" | **Record Count Flow view** (right-click Flow bg → Flow view → record count; enable auto-compute in dataset settings); **Data Quality Rules / Metrics+Checks** (thresholded alerts — e.g. unmatched-join-output rows > 0); **Scenario alerts** (email/Slack with row-count summary); `dku dataset info DS -P PROJ --recompute`. Per-tool count is opt-in because DSS handles datasets bigger than one desktop's memory. |
| "Renamed a column upstream, now I reconfigure every downstream recipe by hand" | **Auto-schema propagation** (recent DSS, enable in project settings — adds/removes/renames flow downstream); **Schema propagation tool** (older DSS — Flow-level dialog, accept recipe-by-recipe). Rename-then-propagate can silently drop the renamed column in some DSS versions — spot-check downstream column lists after a rename. |
| "Alteryx `*Unknown` lets any future column pass through — how in DSS?" | No blanket switch. **Join**: "non-matching columns" passes unmapped cols from either side; **Prepare**: doesn't drop unknown cols (a formula/rename on a missing col no-ops on propagation); **Stack** `--mode UNION` (default): union of cols across inputs. DSS is schema-aware → manual bump per recipe on drift, in exchange for deterministic downstream behavior. Real friction → log specific pain points as a Product request, not a workaround. |
| Flow relies on Alteryx stable-Sort chaining (e.g. `Sort(Name,Start Date)→MultiRowFormula→Unique→Sort(Name,Flag desc)` expects ties to keep the earlier Start-Date order) | **DSS recipes do NOT preserve row order** — `Distinct`, Group, Join, Stack can reorder arbitrarily, so a downstream Sort's *ties* come out unspecified (symptom: every value matches ground truth but order differs within tie groups → set-equal, not sequence-equal). Fix: make the final Sort fully deterministic — add every implicitly-relied-on column as an explicit tie-break key, e.g. `create-sort -s Name -s "Current Flag:desc" -s "Start Date"`. Never assume a DSS recipe carries an upstream sort through. |
| "In Alteryx I disable a Container based on an App selection — how?" | **Split recipe at zone entry**: condition routes all rows to Zone A's output (B empty) or vice versa; downstream merge zone runs on both but only one has rows. Or **scenario step: build zone** (recent DSS) for conditional builds. Empty dataset ≠ cleared dataset — DSS consumes an empty dataset as a valid input; a cleared one breaks the recipe. Always prefer "empty via filter" over "clear in scenario". |
| "I want to drag tools onto wires / rearrange the Flow by hand" | Four real wants: (1)/(2) "Flow redraws and moves my work / without asking" — legit; minimize with Flow Zones. (3) "auto-layout isn't my idea of tidy" — Flow Zones + anchoring; their tidy = sequential, DSS tidy = fewest line-crossings. (4) "throw tools on canvas first, connect later" — workflow difference, not a gap; DSS builds piece-by-piece, enforcing working data + immediate validation (failures caught at edit time, not run time). Don't promise drag-drop — Product request. |
| "I want to drop a Prepare onto the wire between two recipes" | **Insert Recipe** (recent DSS — right-click dataset → insert recipe, reconnects downstream). Remove-and-rewire (snip) or merge two adjacent recipes: no visual path — manual rewire / recreation. |
| "My inputs are Excel files on my laptop" | Files must live in a shared, versioned source before migration. In order: (1) **SharePoint Online / OneDrive / Google Drive / Google Sheets / Dropbox / Box** plugins — pick what the company uses; (2) admin sets up service accounts / OAuth; (3) ideally done before the first user onboards. Single biggest first-day blocker — if the user can't reach their data, nothing else matters. |
| "I hit Run, Alteryx runs the whole workflow — why is DSS complicated about what runs?" | **Incremental build** — builds only changed + downstream (huge win on big flows); build modes (non-recursive / recursive / smart / forced / missing-data-only) — use job previews to see what'll run; **Build Zone** (recent DSS) ≈ Alteryx "build this container"; **Build All Flow Action** exists for peace of mind but discourage as default (slow, defeats incremental model). |
| "I need a multi-sheet Excel with conditional formatting, emailed" | First ask *does it need to be Excel?* — usually "recipient expects it because Alteryx produced it." Alternatives: dataset shared on a Workspace; Dashboard with pivots/charts; Email reporter with a link. If Excel is truly required: **Multisheet Excel export** plugin + DSS conditional formatting (preserved on export). Template range-writes / dynamic per-partition files need a private plugin — contact internal TAM. |
