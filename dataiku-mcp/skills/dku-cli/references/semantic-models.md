# Reference: Semantic Model Payload Schemas

For `set-version` bulk edits. Use `add-*` commands for most ops; drop to JSON for `sqlGenerationConfig`, `foreignKeys`, attribute descriptions.

## Query-time caveat: only NL-to-SQL execution needs SQL-backed datasets

Semantic-model creation works on any dataset type. `create`, `add-entity`,
relationships, metrics, filters, glossary terms, and golden queries all build
fine against Filesystem/UploadedFiles datasets.

The SQL-backed requirement only appears at query time: the Semantic Model Query
tool refuses sources that are "not accessible via SQL". If that happens, sync
the dataset to a SQL connection and repoint `datasetRef` at the SQL dataset
instead of the upstream file source. Do not block or restructure the model
build over this.

## Version

```json
{"description":"","entities":[],"relationships":[],"glossaryTerms":[],"goldenQueries":[]}
```

## Entity

```json
{
  "name": "customer",
  "type": "DATASET",
  "datasetRef": "PROJECT_KEY.dataset_name",
  "primaryKey": {"attributes": ["CustomerID"]},
  "foreignKeys": [],
  "attributes": [],
  "metrics": [],
  "filters": []
}
```

## Attribute

```json
{
  "name": "CustomerID",
  "dssType": "string",
  "type": "COLUMN",
  "column": "CustomerID",
  "distinctValuesHandlingMode": "NONE",
  "indexDistinctValues": false,
  "resolveInUserRequests": false,
  "sqlGenerationConfig": {}
}
```

`distinctValuesHandlingMode`: `NONE` (IDs/measures), `AUTO_INDEX` (filterable dims), `MANUAL` (curated enum via `set-manual-values`).

## Relationship

```json
{
  "firstEntity": "customer",
  "secondEntity": "orders",
  "pseudoSQLExpression": "left.CustomerID = right.CustomerID"
}
```

Field names are `firstEntity`/`secondEntity` (not `leftEntity`/`fromEntity`) —
`firstEntity` aliases to `left.*`, `secondEntity` to `right.*` in the
expression. No `id`/cardinality field on relationships; cardinality is
inferred from each entity's `primaryKey`.

## Metric / Filter

Same shape, live inside entity's `metrics` or `filters` array:
```json
{"name":"Total Customers","pseudoSQLExpression":"COUNT(CustomerID)","created":{}}
```

Metrics use aggregate SQL; filters use WHERE predicates.

## Glossary term

```json
{"id":"<uuid>","term":"customer","description":"...","source":"MANUAL","synonyms":["client","account"]}
```

`id` is auto-generated by `add-glossary-term`.

## Golden query

```json
{"name":"monthly revenue","question":"What was revenue by product last month?","generatedSql":"SELECT ...","created":{}}
```
