# Semantic model payload schemas

For `set-version` bulk edits. Use `add-*` commands for most ops; drop to JSON for `sqlGenerationConfig`, `foreignKeys`, attribute descriptions.

## Version

```json
{"description":"","entities":[],"relationships":[],"glossaryTerms":[],"goldenQueries":[]}
```

## Entity

```json
{
  "name": "customer",
  "type": "DATASET",
  "datasetRef": "PROJECT_KEY.dataset_name",
  "primaryKey": {"attributes": ["CustomerID"]},
  "foreignKeys": [],
  "attributes": [],
  "metrics": [],
  "filters": []
}
```

## Attribute

```json
{
  "name": "CustomerID",
  "dssType": "string",
  "type": "COLUMN",
  "column": "CustomerID",
  "distinctValuesHandlingMode": "NONE",
  "indexDistinctValues": false,
  "resolveInUserRequests": false,
  "sqlGenerationConfig": {}
}
```

`distinctValuesHandlingMode`: `NONE` (IDs/measures), `AUTO_INDEX` (filterable dims), `MANUAL` (curated enum via `set-manual-values`).

## Relationship

```json
{
  "firstEntity": "customer",
  "secondEntity": "orders",
  "pseudoSQLExpression": "left.CustomerID = right.CustomerID"
}
```

Uses `left.*` / `right.*` aliases for entity tables.

## Metric / Filter

Same shape, live inside entity's `metrics` or `filters` array:
```json
{"name":"Total Customers","pseudoSQLExpression":"COUNT(CustomerID)","created":{}}
```

Metrics use aggregate SQL; filters use WHERE predicates.

## Glossary term

```json
{"id":"<uuid>","term":"customer","description":"...","source":"MANUAL","synonyms":["client","account"]}
```

`id` is auto-generated by `add-glossary-term`.

## Golden query

```json
{"name":"monthly revenue","question":"What was revenue by product last month?","generatedSql":"SELECT ...","created":{}}
```
