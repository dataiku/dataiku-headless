# PARALLEL Block

Runs multiple child blocks concurrently. Each child gets a copy of the conversation history and runs in its own thread. Results can be collected into state or scratchpad.

## Param Matrix

| Param | Required | Type | Notes |
|-------|----------|------|-------|
| `id` | yes | string | Unique block identifier |
| `type` | yes | `"PARALLEL"` | |
| `blockIds` | yes | list[string] | IDs of blocks to run in parallel |
| `maxThreads` | no | int | Max concurrent threads (default 32) |
| `generatedOutputStorageLocation` | no | `"STATE"` or `"SCRATCHPAD"` | Where to collect outputs |
| `targetOutputKey` | no | string | Key for collected results |
| `generatedStateKeys` | no | list[string] | State keys generated by children |
| `generatedScratchpadKeys` | no | list[string] | Scratchpad keys generated by children |
| `nextBlock` | yes* | string | Next block after all children complete |

## Canonical Example

```json
{
  "id": "parallel_research",
  "type": "PARALLEL",
  "blockIds": ["check_policies", "predict_risk", "get_stats"],
  "maxThreads": 3,
  "generatedOutputStorageLocation": "STATE",
  "targetOutputKey": "research_results",
  "generatedStateKeys": [],
  "generatedScratchpadKeys": [],
  "nextBlock": "save_findings"
}
```

## Guardrails

1. **Child block state values may be lists.** When children use `SAVE_TO_STATE`, the values stored may be wrapped in a list. Handle this in downstream blocks.
2. **Each child gets a conversation copy.** Children don't see each other's outputs during execution.
3. **Child blocks need `passConversationHistory: true`** to see the conversation from before the parallel block.
4. **Set `maxThreads`** to match the number of children for maximum parallelism.
5. **Scratchpad is isolated per sub-sequence.** Each parallel branch has its own scratchpad scope — scratchpad writes in one branch are not visible to other branches. Use state (with a unique key per branch) for cross-branch communication.
6. **No human-in-the-loop inside Parallel.** The Core Loop (human confirmation, `requireHumanApproval`) cannot be used inside Parallel branches. Tools requiring human approval will fail if invoked from within a Parallel block.
7. **State write race condition.** If multiple branches write the same state key simultaneously, only one value persists. Use unique per-branch state keys (`outputStateKey`) to avoid overwriting.
